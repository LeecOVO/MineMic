# MineMic 移动版 v0.1.0-ea.3

本次 EA 更新重点修复外放参考与回声处理链路，并改善断开、重连和后台状态清理。

## 更新

- 使用 WebRTC 连续 Sinc 重采样匹配 PC 外放与手机麦克风的采样节奏，跟踪独立设备的慢速时钟偏差。
- 改善批量采样、参考乱序及短暂丢包的处理。参考不完整或处理超时，继续传输原始音频或独立降噪结果；回声抑制和降噪仍默认关闭、可单独选择。
- 修复持续时钟同步期间的映射过期与周期性重置问题。加入有上限的输出时间轴，在发送前补入晚到参考的处理结果，保持语音采样顺序；降噪在最终输出上按顺序运行，避免处理路径切换造成断续。
- 开启回声抑制后显示常驻数字监测，按秒显示参考帧、处理覆盖率及回退计数；关闭后隐藏，详细状态不再反复撑高界面。监测回调通过独立的有界通道交付，不占用音频处理线程。覆盖率表示使用 AEC 的帧占比，不代表回声消除程度。
- iOS 和 Android 使用独立串行队列执行声音增强，减少与界面和其他后台任务争用执行机会；处理仍有时限，超时继续传输音频。
- PC 报告的参考采集阶段和异常原因可传到手机，便于定位等待状态；UDP 音频通道异常可独立触发原会话恢复。
- 在本机加密保存最多 4 条恢复凭据，手机 App 进程重启后，再次点击连接可恢复原 PC 占用。凭据文件不进入应用备份；明确断开后清理，未送达的释放通知会在下次连接前重试。
- 主动断开立即停止本机采集、清理会话显示，后台通知对端最多等待 200 ms。意外断线则保留凭据并自动重连，支持配合新版 PC 处理意外重启。
- 清理断开后的 iOS 实时活动与 Android 麦克风通知，隔离旧采集和网络回调，避免过时状态影响新连接。
- 完善 iOS 系统 Liquid Glass 配对方式选择器、关于与隐私说明，并补齐归档中的隐私清单。

## 安装与使用

- Android 7.0+：安装 `MineMic-0.1.0-ea.3-android.apk`，沿用之前 EA 的测试签名。
- iOS 18.2+：`MineMic-0.1.0-ea.3-ios-unsigned.ipa` 与内含实时活动扩展完全无签名，需自行签名后安装。
- 构建号为 `16`，协议仍为 v2。建议同时更新至 [MineMic-PC v0.1.0-ea.7](https://github.com/LeecOVO/MineMic-PC/releases/tag/v0.1.0-ea.7)。
- PC 仍需单独安装虚拟声卡，才能在游戏或会议软件中作为系统麦克风使用。

主动断开时，完全断网可能使通知无法送达；本机仍立即清理，下一次配对前优先尝试释放旧占用。配对码仍只在 PC 停止接收或手动更新时变化。

AEC 路径使用固定 100 ms 参考等待和 40 ms 输出窗口，换取对晚到参考的处理空间；这是代码中的缓冲配置，不是实测端到端延迟。关闭回声抑制不增加这两段等待。

项目继续处于 Early Access。合成回声、漂移与丢包测试不能替代实际房间、扬声器、手机和网络的声音效果、延迟及后台稳定性验证。IPv6 留待后续版本。传输未加密，请在可信局域网使用。

# MineMic Mobile v0.1.0-ea.3

This Early Access update improves playback-reference processing, disconnect responsiveness, reconnection, and background-state cleanup.

- Use WebRTC's continuous Sinc resampler to match playback and microphone sample rates across independent device clocks.
- Improve batched capture, reordered references, and short packet-loss handling. Missing references or processing timeouts fall back to microphone audio or independent noise suppression. Both enhancements remain optional and disabled by default.
- Prevent active clock synchronization from expiring between replies or resetting AEC periodically. A bounded output timeline accepts late processing results before playout, preserves capture order, and runs noise suppression once on the chronological output.
- Show a persistent numeric monitor only while echo cancellation is enabled. Counts update once per second without resizing the status area. Processing coverage describes AEC frame usage, not cancellation effectiveness.
- Run enhancement on a dedicated serial queue on iOS and Android to reduce contention with UI and other background work. Processing remains deadline-bounded, with audio fallback on timeout.
- Surface PC reference diagnostics and recover failed UDP audio transports through the existing authenticated session.
- Keep up to four encrypted, device-local recovery records outside app backups. After an app process restart, tapping Connect can reclaim the existing PC reservation. Explicit disconnects clear the record; a missed release is retried before fresh pairing.
- Disconnect locally immediately and spend at most 200 ms notifying the peer. Unexpected network loss retains the session for reconnection; updated PCs also support unexpected-process-restart recovery.
- End stale iOS Live Activities and Android microphone notifications, and isolate callbacks from retired capture and network sessions.
- Refine the iOS system Liquid Glass pairing selector, About and privacy information, and archive privacy manifests.

Android requires 7.0 or later and retains the previous EA test signing certificate. iOS requires 18.2 or later; the IPA and Live Activity extension are completely unsigned and must be signed before installation. Build number: 16. Protocol remains v2. Update [MineMic-PC to v0.1.0-ea.7](https://github.com/LeecOVO/MineMic-PC/releases/tag/v0.1.0-ea.7) for the matching fixes.

A separate virtual audio cable is still required on the PC. During a complete network outage, peer notification cannot be guaranteed; local cleanup remains immediate, and a missed release is retried before fresh pairing.

The AEC path uses a fixed 100 ms reference wait and a 40 ms output window to accommodate late references. These are configured buffers, not a measured end-to-end latency claim. Disabling AEC removes both waits.

This remains Early Access. Synthetic echo, drift, and loss tests do not establish real-device sound quality, latency, or background stability. IPv6 remains pending. Use a trusted LAN; transport is not encrypted.
